# План проекта

## Подготовка · 25 ноября 2026 года

Исходные требования и восемь ссылок сохранены в [описании проекта](../README.md). Доступ через Figma MCP подтверждён для всех восьми узлов. Ближайшая контрольная точка — согласовать реестр компонентов, состояний и стилей после инвентаризации.

## Этап 1. Инвентаризация макета

- Прочитать главную и семь разделов дизайн-системы. Записать названия узлов, вложенные группы, размеры фреймов и доступные версии для разных ширин.
- Зафиксировать цвета, текстовые стили, шрифты, отступы, сетки, радиусы, обводки и эффекты там, где они заданы в макете. Для каждого значения сохранить ссылку на источник.
- Составить реестр компонентов, вариантов и состояний по всем семи разделам. Для главной указать порядок секций, используемые компоненты и необходимые изображения.
- Отдельно вынести вопросы, влияющие на реализацию, например поведение элемента, для которого в макете показан только один вид.

**Приёмка.** Каждый исходный раздел отражён в реестре. По любой записи можно открыть соответствующий узел. Пользователь проверяет полноту реестра и решения по открытым вопросам.

**Результат 25 ноября 2026 года.** Пользователь принял [реестр макета и четыре решения по вёрстке](inventory.md). В Figma проверены все 497 уникальных узлов, на которые ссылается реестр.

## Этап 2. Дизайн-система в коде

- Настроить Vite для HTML, SCSS и модульного JavaScript.
- Перенести подтверждённые значения в общие переменные стилей. Создать БЭМ-блоки и модули поведения по реестру.
- Собрать локальную демонстрационную страницу со всеми компонентами и состояниями. Для интерактивных элементов проверить управление мышью и клавиатурой.
- В Markdown связать каждый компонент с узлом Figma и примером в проекте. Добавить команды запуска и сборки после их проверки.

**Приёмка.** Сборка проходит. Каждый элемент реестра можно открыть на демонстрационной странице и сравнить с макетом. Пользователь принимает дизайн-систему перед вёрсткой главной.

**Результат 25 ноября 2026 года.** Пользователь принял [дизайн-систему из 62 разделов и 312 образцов](design-system.md) и закрыл этап. Проверены чистая установка и сборка, узлы и прямые ссылки, внешний вид, мышь и клавиатура. Следующий согласуемый этап — главная страница.

## Этап 3. Главная страница

- Собрать секции в порядке узла `26:278`, используя принятые компоненты и стили.
- Подготовить локальные ресурсы. Для растровых изображений проверить качество WebP, для векторных использовать исходники макета.
- Реализовать согласованное поведение и компоновку для подтверждённых размеров экрана.

**Приёмка.** Все секции на месте, изображения загружаются, согласованные сценарии работают. Главная доступна из сборки Vite.

**Проверка 25 ноября 2026 года.** В собранной версии открываются [главная](http://127.0.0.1:4173/) и [каталог](http://127.0.0.1:4173/catalog/). В Chrome проверены три настольных варианта и ширины 1200, 1000, 768 и 375 px. В каждом варианте 17 секций. Для каждой из 79 растровых позиций проверено совпадение идентификатора локального WebP с видимой заливкой соответствующего слоя Figma. На двух узких макетах сохранена одна секция коллекций сразу после галереи. Проверены загрузка локальных ресурсов, выбор товарных меток, корзина, избранное, сравнение, ленты мышью и клавиатурой, смена темы, поиск, меню, отзывы, проверка адреса подписки и возврат фокуса после закрытия окна. В каталоге повторно проверены все 312 образцов. Полная визуальная сверка запланирована на этап 4.

**Результат 25 ноября 2026 года.** Пользователь принял главную и закрыл этап 3. Внешние адреса, обработчик подписки и видеофайлы ожидают исходных данных.

## Этап 4. Визуальная сверка и сдача

- Сравнить снимки страницы с Figma на ширинах исходных фреймов. Между заданными ширинами проверить переносы текста, переполнение и доступность элементов управления.
- Исправить расхождения, проверить итоговую сборку и повторно пройти основные сценарии.
- Зафиксировать в Markdown условия проверки, результаты и согласованные отклонения.

**Приёмка.** По инструкции из репозитория можно запустить проект и воспроизвести проверку. Пользователь принимает главную по результатам сверки.

## Порядок работы

После согласования плана каждый этап ведём в отдельном чате проекта с собственным встроенным планом. Вопросы и приёмка шагов остаются в чате этапа. В родительский чат передаём один итог после закрытия этапа. Документацию обновляем вместе с кодом, завершённые изменения фиксируем в Git.
